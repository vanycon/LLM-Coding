## Architektur
### Use Case UC-05: Wartung abschließen
1. **Trigger**: Wart hat Wartung eines wartungsfälligen Gegenstands durchgeführt
2. **Validierung**: Gegenstand muss `wartungsfaellig` sein
3. **Zustandsübergang**: 
   - Gegenstand: `wartungsfaellig` → `verfügbar` oder `reserviert`
   - Nutzungszähler: → 0
4. **Vormerkung-Handling** (BR-VOR-03):
   - Wenn offene Vormerkung für Kategorie existiert: Gegenstand → `RESERVIERT`
   - Sonst: Gegenstand → `VERFUEGBAR`

### Business Rules implementiert
- **BR-WAR-03**: Gegenstand verfügbar, Nutzungszähler = 0
- **BR-VOR-03**: Erste offene Vormerkung reserviert den Gegenstand

### Key Design Decisions
1. **Keine separate Port**: `GegenstandRepository.update()` reicht (atomar)
2. **Vormerkung ist nicht-invasiv**: Service prüft nur, ändert nichts
3. **RESERVIERT-Zustand**: Erste Implementation, später UC-01 erweitern
4. **Hamburg-Style TDD**: Tests first, Service implementiert die Logik
