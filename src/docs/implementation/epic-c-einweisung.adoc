= EPIC-C: Einweisung
:toc:

Muss vor EPIC-A abgeschlossen sein, weil BR-AUS-04 (Ausgabe-Ablehnung bei fehlender
Einweisung) sonst nicht vollständig getestet werden kann.

== User Story C1 — Einweisung erfassen (UC-07)

Als *Wart* möchte ich eine Einweisung für ein Mitglied und eine Kategorie erfassen, damit
das Mitglied anschließend einweisungspflichtige Gegenstände dieser Kategorie ausleihen darf.

* Referenz: UC-07 (`spec-use-cases.adoc`), BR-EIN-01, BR-EIN-02 (`spec-domain-model.adoc`).
* Akzeptanzkriterien: `einweisung-erfassen.feature` (`spec-acceptance-criteria.adoc`).
* Priorität: *Must* — ohne diese Story bleibt BR-AUS-04 in EPIC-A ungetestet.
* Duplikatsregel (REQ-UC07-02) ist Teil der Story, nicht nachträglich zu ergänzen.

== User Story C2 — Einweisung widerrufen (UC-08)

Als *Wart* möchte ich eine Einweisung widerrufen können, damit ein Mitglied, dem ich nicht
mehr zutraue, mit einer Kategorie sicher umzugehen, keine einweisungspflichtigen Gegenstände
mehr ausgeliehen bekommt.

* Referenz: UC-08 (`spec-use-cases.adoc`), BR-EIN-03.
* Akzeptanzkriterien: `einweisung-widerrufen.feature`.
* Priorität: *Should* — EPIC-A funktioniert bereits mit C1 allein; der Widerruf ist ein
  Korrekturpfad, kein Blocker für den Kernprozess.

== Reihenfolge

C1 vor C2 (kein Widerruf ohne vorhandene Einweisung). C1 vor EPIC-A (BR-AUS-04-Abhängigkeit,
siehe `backlog.adoc`).
