= EPIC-F: Verlust melden (UC-06 / SI-06)

Analyse-Dokument für die Implementierung von UC-06 (Gegenstand als verloren melden).

== Scope

=== Use Case
* **UC-06: Verlust melden** (Primary Actor: Wart)
  - Precondition: Eine aktive Ausleihe existiert für den Gegenstand
  - Main Success Scenario: Wart erfasst Verlust → System schließt Ausleihe ab, behält Kaution ein, mustert Gegenstand aus
  - Extension 1a: Keine aktive Ausleihe → Ablehnung

=== Business Rules
* **BR-VER-01**: Verlust ist ein eigenständiger Vorgang, **ohne** Prüfprotokoll
* **BR-VER-02**: Verlust-Ereignis schließt die Ausleihe ab, unabhängig von Rückgabe/Prüfung
* **BR-VER-03**: Verlust → vollständige Kautionseinbehaltung + Ausmusterung (= BR-KAU-03)
* **BR-KAU-03**: Verloren = Kaution 100% einbehalten
* **BR-KAU-04**: Jede Kautionsbewegung erzeugt Eintrag mit Zeitstempel, Betrag, Auslöser

=== Akzeptanzkriterien (aus `verlust-melden.feature`)
* ✅ Verlust erfasst → Ausleihe wird VERLOREN (neuer Zustand)
* ✅ Kaution wird 100% einbehalten → Kautionsbewegung-Eintrag
* ✅ Gegenstand wird auf AUSGEMUSTERT gesetzt (neuer Zustand)
* ✅ Verlust für unbekannte Ausleihe wird abgelehnt (404)
* ✅ Verlust für nicht-aktive Ausleihe wird abgelehnt (409)

== State Transitions

=== Ausleihe-Zustand
[plantuml, uc-06-ausleihe-state, svg]
----
state AKTIV
state ZURUECKGEGEBEN
state IN_PRUEFUNG
state VERLOREN [new]

AKTIV --> ZURUECKGEGEBEN: gegenstand_zuruecknehmen (UC-03)
AKTIV --> IN_PRUEFUNG: (UC-03, nach Rückgabe)
IN_PRUEFUNG --> ZURUECKGEGEBEN: pruefung_abschliessen (UC-04)
ZURUECKGEGEBEN --> [*]

AKTIV --> VERLOREN: verlust_erfassen (UC-06 **NEU**)
VERLOREN --> [*]
----

**Neu:** VERLOREN ist ein Endzustand (wie ZURUECKGEGEBEN nach Prüfung). Kein Übergang zurück.

=== Gegenstand-Zustand
[plantuml, uc-06-gegenstand-state, svg]
----
state VERFUEGBAR
state AUSGELIEHEN
state IN_PRUEFUNG
state AUSGEMUSTERT [new]

VERFUEGBAR --> AUSGELIEHEN: gegenstand_ausgeben (UC-01)
AUSGELIEHEN --> IN_PRUEFUNG: gegenstand_zuruecknehmen (UC-03)
IN_PRUEFUNG --> VERFUEGBAR: pruefung_abschliessen (UC-04, kein Schaden)

AUSGELIEHEN --> AUSGEMUSTERT: verlust_erfassen (UC-06 **NEU**)
IN_PRUEFUNG --> AUSGEMUSTERT: (UC-04, wenn Schaden >= Wert; oder UC-06 parallel)
AUSGEMUSTERT --> [*]
----

**Neu:** AUSGEMUSTERT ist Terminal. Kein Verleihen mehr möglich.

== Domain Model

=== Aggregates & Enums

**Ausleihe.zustand** erweitert um:
```python
class AusleiheZustand(Enum):
    AKTIV = "aktiv"
    ZURUECKGEGEBEN = "zurueckgegeben"
    VERLOREN = "verloren"  # NEW
```

**Gegenstand.zustand** erweitert um:
```python
class GegenstandZustand(Enum):
    VERFUEGBAR = "verfuegbar"
    AUSGELIEHEN = "ausgeliehen"
    IN_PRUEFUNG = "in_pruefung"
    AUSGEMUSTERT = "ausgemustert"  # NEW
```

=== Integration mit Kaution

**Kautionsbewegung** (existiert schon, neu getestet):
```python
@dataclass
class Kautionsbewegung:
    ausleihe_id: str
    betrag_cent: int          # +: hinterlegt, -: abzug/freigabe
    grund: str                # "hinterlegung", "abzug_prüfung", "freigabe", "verlust_volleinzug"
    zeitstempel: str          # ISO-String
    # impliziert: Auslöser ist der aktuell eingeloggte Wart
```

**Verlust erzeugt Kautionsbewegung:**
- Grund: "verlust_volleinzug"
- Betrag: `-ausleihe.kaution_cent` (100% Einzug)

== Validierungsreihenfolge (Service-Layer)

**Eingang:** `verlust_erfassen(ausleihe_repo, gegenstand_repo, kautionsbewegung_repo, clock, ausleihe_id) → Ausleihe | VerlustAblehnung`

1. **Ausleihe existiert?** → `ausleihe_repo.find_by_id(ausleihe_id)` → None → `AusleiheNichtGefunden`
2. **Ausleihe aktiv?** → `ausleihe.zustand == AKTIV` → sonst `AusleiheNichtAktiv` (409)
3. **Gegenstand existiert?** → `gegenstand_repo.find_by_inventarnummer(ausleihe.gegenstand_id)` → None → `GegenstandNichtGefunden`
4. **Aktion durchführen:**
   a. Ausleihe-Zustand ändern: `AKTIV` → `VERLOREN`
   b. Gegenstand-Zustand ändern: beliebig → `AUSGEMUSTERT`
   c. Kautionsbewegung erzeugen: `grund="verlust_volleinzug"`, `betrag_cent=-ausleihe.kaution_cent`

== REST-Endpunkt (SI-06)

**Request:**
```
POST /ausleihen/{ausleiheId}/verlust
Headers: X-Rolle: wart
```

**Success Response (201 Created):**
```json
{
  "ausleiheId": "A-42",
  "gegenstandes": "LS-007",
  "mitgliedId": "M-99",
  "zustand": "verloren",
  "kaution_cent": 5000,
  "verlust_datum": "2026-08-19T08:20:00"
}
```

**Error Responses:**
- `404 AUSLEIHE_NICHT_GEFUNDEN`: Ausleihe existiert nicht
- `409 AUSLEIHE_NICHT_AKTIV`: Ausleihe ist nicht mehr aktiv (z.B. schon zugeführt)
- `403 ROLLE_NICHT_BERECHTIGT`: Nur Wart darf Verlust melden

== Test-Strategie

=== Service-Layer Tests
1. **Happy Path**: Verlust erfassen, Ausleihe + Gegenstand + Kaution-Bewegung korrekt aktualisiert
2. **Validierung:**
   - Ausleihe nicht gefunden (404)
   - Ausleihe nicht aktiv (409)
   - Gegenstand nicht gefunden (404)
3. **Kaution-Integrität**: Kautionsbewegung mit korrektem Betrag (-100%)
4. **Zustandsübergänge**: Vorher/nachher Gegenstand- und Ausleihe-Zustand checken

=== REST-Layer Tests
5. **Happy Path**: POST /ausleihen/{id}/verlust mit X-Rolle: wart → 201
6. **Fehlerhafte Rolle**: Ohne X-Rolle oder falsche Rolle → 403
7. **Not Found**: POST mit unbekannter ausleiheId → 404

=== Edge Cases (Schema-Ebene)
8. **Database Constraint**: ausleihe.zustand CHECK-Constraint aktualisiert? Nur erlaubte Werte

== Abhängigkeiten

✅ **EPIC-A** (UC-01, UC-03): Ausleihe, Gegenstand, Zustandsverwaltung — existiert
✅ **EPIC-B** (UC-04): Kaution, Kautionsbewegung — existiert
❌ **Nicht abhängig von:** UC-05 (Wartung), UC-11 (Vormerkung) — Verlust ist isoliert

== Umsetzungs-Meilensteine

1. **Domain**: Neue Zustände (VERLOREN, AUSGEMUSTERT) hinzufügen
2. **Schema**: `ausleihe.zustand` + `gegenstand.zustand` CHECK-Constraints erweitern
3. **Service**: `verlust_erfassen()` mit Validierungslogik
4. **REST**: POST /ausleihen/{ausleiheId}/verlust Endpunkt
5. **Tests**: 8+ Testfälle (Service + REST)
6. **Commit**: "EPIC-F: Verlust melden (UC-06 / SI-06) complete"
