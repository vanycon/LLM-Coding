== Description
Provide one transaction boundary for each state-changing use case, conflict protection for concurrent commands, and an injectable clock for overdue and calendar-expiry rules.

== Acceptance Criteria
[source,gherkin]
----
Given a state-changing operation updates domain state and required ledger records
When any part fails
Then all changes roll back
Given two commands compete for one item or returned loan
When both execute concurrently
Then only one valid state transition commits
And duplicate loan, collection, return, inspection, or reservation records are impossible
Given tests supply a controlled current date
When overdue or reservation expiry is evaluated
Then calendar-date behavior is deterministic
----
