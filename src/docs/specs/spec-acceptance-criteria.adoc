Jedes Szenario nennt seine Use-Case-ID und die geprüfte BR-ID im Titel oder als Tag, damit Tests
in der Implementierungsphase direkt darauf verweisen können (siehe `AGENTS.md`, Definition of
Done). Die Feature-Dateien sind hier inline dokumentiert; in der Implementierung liegen sie unter
`src/test/resources/features/` (oder äquivalent, je nach gewähltem Test-Stack).

== gegenstand-ausgeben.feature (UC-01)

[source,gherkin]
----
Feature: Gegenstand ausgeben

  @UC-01 @BR-AUS-01
  Scenario: Ausgabe eines verfügbaren Gegenstands
    Given ein Gegenstand "BH-01" im Zustand "verfuegbar"
    And ein Mitglied "M-1" ohne Sperre
    When der Thekendienst "BH-01" an "M-1" ausgibt
    Then wird die Ausgabe angenommen
    And der Gegenstand "BH-01" wechselt in den Zustand "ausgeliehen"

  @UC-01 @BR-AUS-01
  Scenario: Ausgabe eines ausgeliehenen Gegenstands wird abgelehnt
    Given ein Gegenstand "BH-01" im Zustand "ausgeliehen"
    And ein Mitglied "M-1" ohne Sperre
    When der Thekendienst "BH-01" an "M-1" ausgibt
    Then wird die Ausgabe mit "GEGENSTAND_NICHT_VERFUEGBAR" abgelehnt

  @UC-01 @BR-AUS-03
  Scenario: Ausgabe an gesperrtes Mitglied wird abgelehnt
    Given ein Gegenstand "BH-01" im Zustand "verfuegbar"
    And ein Mitglied "M-2" mit einer überfälligen Ausleihe
    When der Thekendienst "BH-01" an "M-2" ausgibt
    Then wird die Ausgabe mit "MITGLIED_GESPERRT" abgelehnt

  @UC-01 @BR-AUS-02
  Scenario: Viertes gleichzeitiges Ausleihen wird abgelehnt
    Given ein Mitglied "M-3" mit drei aktiven Ausleihen
    And ein Gegenstand "KS-01" im Zustand "verfuegbar"
    When der Thekendienst "KS-01" an "M-3" ausgibt
    Then wird die Ausgabe mit "AUSLEIHLIMIT_ERREICHT" abgelehnt

  @UC-01 @BR-AUS-02
  Scenario: Zurückgegebene, aber ungeprüfte Ausleihe zählt gegen das Limit
    Given ein Mitglied "M-4" mit zwei aktiven Ausleihen und einer zurückgegebenen, noch nicht geprüften Ausleihe
    And ein Gegenstand "KS-02" im Zustand "verfuegbar"
    When der Thekendienst "KS-02" an "M-4" ausgibt
    Then wird die Ausgabe mit "AUSLEIHLIMIT_ERREICHT" abgelehnt

  @UC-01 @BR-AUS-04
  Scenario: Einweisungspflichtiger Gegenstand ohne Einweisung wird abgelehnt
    Given ein Gegenstand "KS-03" der Kategorie "Kettensaege" mit Einweisungspflicht
    And ein Mitglied "M-5" ohne Einweisung für Kategorie "Kettensaege"
    When der Thekendienst "KS-03" an "M-5" ausgibt
    Then wird die Ausgabe mit "EINWEISUNG_FEHLT" abgelehnt

  @UC-01 @BR-AUS-05 @BR-KAT-04
  Scenario Outline: Kautionsberechnung bei Ausgabe
    Given ein Gegenstand mit Wiederbeschaffungswert <wbw> Cent im Zustand "verfuegbar"
    And ein Mitglied ohne Sperre
    When der Thekendienst den Gegenstand ausgibt
    Then beträgt die hinterlegte Kaution <kaution> Cent

    Examples:
      | wbw    | kaution |
      | 10000  | 2000    |
      | 1000   | 500     |
      | 60000  | 10000   |
      | 2000   | 500     |
----

== ausleihe-verlaengern.feature (UC-02)

[source,gherkin]
----
Feature: Ausleihe verlängern

  @UC-02 @BR-AUS-06
  Scenario: Erste Verlängerung wird angenommen
    Given eine aktive, nicht überfällige, noch nicht verlängerte Ausleihe "A-1"
    When der Thekendienst "A-1" verlängert
    Then wird die Verlängerung angenommen
    And die Rückgabefrist verschiebt sich um die Leihdauer der Kategorie

  @UC-02 @BR-AUS-06
  Scenario: Zweite Verlängerung wird abgelehnt
    Given eine bereits einmal verlängerte, aktive Ausleihe "A-2"
    When der Thekendienst "A-2" erneut verlängert
    Then wird die Verlängerung mit "BEREITS_VERLAENGERT" abgelehnt

  @UC-02 @BR-AUS-07
  Scenario: Verlängerung einer überfälligen Ausleihe wird abgelehnt
    Given eine überfällige Ausleihe "A-3"
    When der Thekendienst "A-3" verlängert
    Then wird die Verlängerung mit "AUSLEIHE_UEBERFAELLIG" abgelehnt

  @UC-02 @BR-AUS-07
  Scenario: Verlängerung bei offener Vormerkung wird abgelehnt
    Given eine aktive Ausleihe "A-4" der Kategorie "Beamer"
    And eine offene Vormerkung für Kategorie "Beamer"
    When der Thekendienst "A-4" verlängert
    Then wird die Verlängerung mit "VORMERKUNG_OFFEN" abgelehnt

  @UC-02 @BR-AUS-08
  Scenario: Sperre blockiert Verlängerung einer anderen, nicht überfälligen Ausleihe
    Given ein Mitglied "M-6" mit einer überfälligen Ausleihe "A-5"
    And eine weitere, nicht überfällige Ausleihe "A-6" desselben Mitglieds "M-6"
    When der Thekendienst "A-6" verlängert
    Then wird die Verlängerung mit "MITGLIED_GESPERRT" abgelehnt

  @UC-02 @BR-AUS-09
  Scenario: Kaution bleibt bei Verlängerung unverändert
    Given eine aktive Ausleihe "A-7" mit hinterlegter Kaution von 2000 Cent
    And der Wiederbeschaffungswert der Kategorie hat sich seit der Ausgabe geändert
    When der Thekendienst "A-7" verlängert
    Then bleibt die hinterlegte Kaution bei 2000 Cent
----

== gegenstand-zuruecknehmen.feature (UC-03)

[source,gherkin]
----
Feature: Gegenstand zurücknehmen

  @UC-03 @BR-RUP-01
  Scenario: Rückgabe versetzt Gegenstand in Prüfung, ohne die Ausleihe abzuschließen
    Given eine aktive Ausleihe "A-8" für Gegenstand "NM-01"
    When der Thekendienst "A-8" zurücknimmt
    Then wechselt "NM-01" in den Zustand "in_pruefung"
    And bleibt die Ausleihe "A-8" nicht abgeschlossen

  @UC-03 @BR-RUP-02
  Scenario: Auffälligkeiten werden als Freitext erfasst, ohne den Kautionsabzug festzulegen
    Given eine aktive Ausleihe "A-9"
    When der Thekendienst "A-9" mit Auffälligkeit "Riss im Gehäuse" zurücknimmt
    Then wird die Auffälligkeit als Freitext an "A-9" gespeichert
    And es entsteht kein Kautionsabzug durch diese Erfassung

  @UC-03
  Scenario: Erneute Rückgabe einer bereits zurückgegebenen Ausleihe wird abgelehnt
    Given eine Ausleihe "A-10" im Zustand "zurueckgegeben"
    When der Thekendienst "A-10" erneut zurücknimmt
    Then wird die Rückgabe mit "BEREITS_ZURUECKGEGEBEN" abgelehnt
----

== pruefung-abschliessen.feature (UC-04)

[source,gherkin]
----
Feature: Prüfung abschließen

  @UC-04 @BR-RUP-04
  Scenario: Prüfprotokoll schließt die Ausleihe ab
    Given eine Ausleihe "A-11" im Zustand "zurueckgegeben"
    When der Wart die Prüfung für "A-11" mit Kautionsabzug 0 Cent abschließt
    Then ist die Ausleihe "A-11" abgeschlossen

  @UC-04 @BR-RUP-05
  Scenario: Bereits vermerkter Mangel wird nicht erneut der Ausleihe zugerechnet
    Given ein Gegenstand mit einem Mängel-Eintrag "Kratzer am Gehäuse" aus einer früheren Prüfung
    And eine Ausleihe "A-12" für diesen Gegenstand im Zustand "zurueckgegeben"
    When der Wart die Prüfung für "A-12" mit dem gemeldeten Schaden "Kratzer am Gehäuse" abschließt
    Then wird "Kratzer am Gehäuse" nicht der Ausleihe "A-12" zugerechnet

  @UC-04 @BR-RUP-05
  Scenario: Neuer Schaden wird der laufenden Ausleihe zugerechnet
    Given eine Ausleihe "A-13" im Zustand "zurueckgegeben" ohne bekannte Mängel am Gegenstand
    When der Wart die Prüfung für "A-13" mit neuem Schaden "Riss im Griff" abschließt
    Then wird "Riss im Griff" der Ausleihe "A-13" zugerechnet
    And wird "Riss im Griff" der Mängelliste des Gegenstands hinzugefügt

  @UC-04 @BR-KAU-02
  Scenario: Kautionsabzug über der hinterlegten Kaution wird abgelehnt
    Given eine Ausleihe "A-14" mit hinterlegter Kaution von 2000 Cent im Zustand "zurueckgegeben"
    When der Wart die Prüfung für "A-14" mit Kautionsabzug 2500 Cent abschließen will
    Then wird die Erfassung mit "ABZUG_UEBERSTEIGT_KAUTION" abgelehnt

  @UC-04 @BR-KAU-01 @BR-KAU-04
  Scenario: Kaution wird abzüglich des Abzugs freigegeben und gebucht
    Given eine Ausleihe "A-15" mit hinterlegter Kaution von 2000 Cent im Zustand "zurueckgegeben"
    When der Wart die Prüfung für "A-15" mit Kautionsabzug 500 Cent abschließt
    Then werden 1500 Cent freigegeben
    And entsteht ein Kautionsbewegungs-Eintrag mit Zeitstempel, Betrag und Auslöser

  @UC-04 @BR-WAR-01 @BR-WAR-02
  Scenario: Erreichtes Wartungsintervall führt zu wartungsfällig statt verfügbar
    Given ein Gegenstand mit Wartungsintervall 20 und Nutzungszähler 19
    And eine Ausleihe im Zustand "zurueckgegeben" für diesen Gegenstand
    When der Wart die Prüfung abschließt
    Then erhöht sich der Nutzungszähler auf 20
    And wechselt der Gegenstand in den Zustand "wartungsfaellig"

  @UC-04 @BR-VOR-03
  Scenario: Verfügbar werdender Gegenstand wird für die Warteschlange reserviert
    Given ein Gegenstand unterhalb des Wartungsintervalls, im Zustand "zurueckgegeben"
    And eine offene Vormerkung für die Kategorie des Gegenstands
    When der Wart die Prüfung abschließt
    Then wechselt der Gegenstand in den Zustand "reserviert"
    And ist er für das erste Mitglied der Warteschlange reserviert

  @UC-04 @BR-VOR-05
  Scenario: Wartungsfällig gewordener Gegenstand erzeugt keine Reservierung
    Given ein Gegenstand am Wartungsintervall, im Zustand "zurueckgegeben"
    And eine offene Vormerkung für die Kategorie des Gegenstands
    When der Wart die Prüfung abschließt
    Then wechselt der Gegenstand in den Zustand "wartungsfaellig"
    And bleibt die Warteschlange der Kategorie unverändert
----

== katalog-pflegen.feature (UC-09)

[source,gherkin]
----
Feature: Katalog pflegen

  @UC-09 @BR-KAT-01
  Scenario: Gegenstand mit bereits vergebener Inventarnummer wird abgelehnt
    Given ein Gegenstand mit Inventarnummer "BH-01" existiert bereits
    When der Wart einen weiteren Gegenstand mit Inventarnummer "BH-01" anlegt
    Then wird das Anlegen mit "INVENTARNUMMER_VERGEBEN" abgelehnt

  @UC-09 @BR-KAT-05
  Scenario: Geänderte Leihdauer wirkt nur auf künftige Ausleihen
    Given eine Kategorie "Beamer" mit Leihdauer 7 Tagen
    And eine laufende Ausleihe eines Gegenstands der Kategorie "Beamer" mit Rückgabefrist auf Basis von 7 Tagen
    When der Wart die Leihdauer von "Beamer" auf 14 Tage ändert
    Then bleibt die Rückgabefrist der laufenden Ausleihe unverändert
    And erhält eine ab jetzt neu ausgegebene Ausleihe der Kategorie "Beamer" eine Rückgabefrist auf Basis von 14 Tagen

  @UC-09 @BR-KAT-06
  Scenario: Geändertes Wartungsintervall wirkt sofort auf den aktuellen Nutzungszähler
    Given eine Kategorie "Kettensaege" mit Wartungsintervall 20
    And einen Gegenstand der Kategorie "Kettensaege" mit Nutzungszähler 15
    When der Wart das Wartungsintervall von "Kettensaege" auf 15 ändert
    And der Wart die nächste Prüfung dieses Gegenstands abschließt
    Then wechselt der Gegenstand in den Zustand "wartungsfaellig"
----

== reservierung-verfall.feature (Systemreaktion, BR-VOR-04)

[source,gherkin]
----
Feature: Verfall einer Reservierung

  @BR-VOR-04
  Scenario: Reservierung verfällt nach drei Kalendertagen, nächstes Mitglied rückt nach
    Given ein Gegenstand, reserviert für Mitglied "M-16" seit 3 Kalendertagen
    And eine weitere Vormerkung von Mitglied "M-17" in derselben Warteschlange
    When das heutige Datum ausgewertet wird

    And wird der Gegenstand für "M-17" reserviert

  @BR-VOR-04 @BR-VOR-10
  Scenario: Reservierungsfrist gilt kalendarisch, auch außerhalb der Öffnungstage
    Given ein Gegenstand, reserviert für ein Mitglied seit dem 2026-08-14 (Freitag)
    When das heutige Datum 2026-08-17 (Montag) ist
    Then ist die Reservierung verfallen, obwohl der Verein nur dienstags und samstags öffnet
