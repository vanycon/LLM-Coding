Anmerkungen::
* `Mitglied.gesperrt` ist kein gespeichertes Feld, sondern aus BR-SPE-01/02 abgeleitet: wahr,
  solange mindestens eine Ausleihe des Mitglieds überfällig ist (siehe <<Sperre>>).
* `Ausleihe.zustand` und `Gegenstand.zustand` sind eigenständige State Machines
  (siehe <<Zustandsautomaten>>) — der Gegenstandszustand folgt nicht automatisch dem
  Ausleihezustand (Glossar: Rückgabe beendet die Ausleihe nicht).
* `MaengelEintrag` ist die in `prd-klaerungen.adoc` geforderte strukturierte Mängelliste je
  Gegenstand (BR-RUP-05) — kein Freitextvergleich früherer Prüfprotokolle.

[[Zustandsautomaten]]
== Zustandsautomaten

=== Gegenstand

.State Machine Gegenstand
[plantuml, state-gegenstand, svg]
----
@startuml
[*] --> verfuegbar
verfuegbar --> ausgeliehen : UC-01 Ausgabe [BR-AUS-01, BR-AUS-05]
verfuegbar --> reserviert : UC-04/UC-05 Reservierung entsteht [BR-VOR-03]
reserviert --> ausgeliehen : UC-01 Ausgabe an reserviertes Mitglied [BR-AUS-01]
reserviert --> verfuegbar : Reservierung verfällt, keine weitere Vormerkung [BR-VOR-04]
reserviert --> reserviert : Reservierung verfällt, nächstes Mitglied [BR-VOR-04]
ausgeliehen --> in_pruefung : UC-03 Rückgabe [BR-RUP-01]
in_pruefung --> verfuegbar : UC-04 Prüfung ohne Wartungsfälligkeit [BR-RUP-06]
in_pruefung --> reserviert : UC-04 Prüfung, Gegenstand verfügbar, Vormerkung vorhanden [BR-VOR-03]
in_pruefung --> wartungsfaellig : UC-04 Prüfung, Wartungsintervall erreicht [BR-WAR-02]
in_pruefung --> ausgemustert : UC-04 Prüfung, irreparabel [BR-RUP-06]
wartungsfaellig --> verfuegbar : UC-05 Wartung abgeschlossen [BR-WAR-03]
wartungsfaellig --> reserviert : UC-05 Wartung abgeschlossen, Vormerkung vorhanden [BR-VOR-03]
ausgeliehen --> ausgemustert : UC-06 Verlust gemeldet [BR-VER-03]
ausgemustert --> [*]
@enduml
----

Invarianten::
* In den Zuständen `ausgeliehen`, `in_pruefung`, `wartungsfaellig` und `ausgemustert` findet keine
  Ausgabe statt (BR-AUS-01, BR-WAR-04).
* `ausgemustert` ist ein Endzustand ohne ausgehende Transition (Glossar).

=== Ausleihe

.State Machine Ausleihe
[plantuml, state-ausleihe, svg]
----
@startuml
[*] --> aktiv : UC-01 Ausgabe
aktiv --> aktiv : UC-02 Verlängerung [BR-AUS-06]
aktiv --> zurueckgegeben : UC-03 Rückgabe [BR-RUP-01]
zurueckgegeben --> abgeschlossen : UC-04 Prüfprotokoll [BR-RUP-04]
aktiv --> abgeschlossen_verloren : UC-06 Verlust [BR-VER-01, BR-VER-02]
abgeschlossen --> [*]
abgeschlossen_verloren --> [*]

note right of aktiv
  überfällig ist ein abgeleitetes Prädikat
  (BR-SPE-02), kein eigener Zustand:
  rueckgabefrist < heute und noch nicht
  zurückgegeben.
end note
@enduml
----

Invarianten::
* Eine Ausleihe zählt gegen das Drei-Ausleihen-Limit des Mitglieds (BR-AUS-02) in den Zuständen
  `aktiv` und `zurueckgegeben` — erst `abgeschlossen`/`abgeschlossen_verloren` zählt nicht mehr.
* `verlaengert` ist ein einmalig von `false` auf `true` schaltbares Flag (BR-AUS-06); kein Zustand
  mit Rücktransition.

[[Sperre]]
=== Mitglied — Sperre (abgeleitet)

.State Machine Sperre
[plantuml, state-sperre, svg]
----
@startuml
[*] --> nicht_gesperrt
nicht_gesperrt --> gesperrt : mindestens eine Ausleihe wird überfällig [BR-SPE-01, BR-SPE-02]
gesperrt --> nicht_gesperrt : Prüfung aller überfälligen Ausleihen abgeschlossen [BR-SPE-03]
gesperrt --> gesperrt : weitere Ausleihe wird überfällig
@enduml
----

Diese State Machine hat keinen eigenen Auslöser-Endpunkt. Sie wird bei jeder Prüfung des
Ausgabe- oder Verlängerungs-Anwendungsfalls (UC-01, UC-02) sowie bei der Reservierungsvergabe
(UC-04, UC-05) aus dem aktuellen Datum und den offenen Rückgabefristen neu berechnet
(BR-SPE-02: `rueckgabefrist < heute AND zustand NOT IN (zurueckgegeben, abgeschlossen, abgeschlossen_verloren)`).

=== Vormerkung / Reservierung

.State Machine Vormerkung
[plantuml, state-vormerkung, svg]
----
@startuml
[*] --> wartend : UC-11 Vormerkung anlegen [BR-VOR-01, BR-VOR-02]
wartend --> reserviert_fuer_mich : Gegenstand wird für dieses Mitglied reserviert [BR-VOR-03]
reserviert_fuer_mich --> abgeholt : UC-01 Ausgabe an dieses Mitglied
reserviert_fuer_mich --> wartend : Reservierung verfällt (3 Kalendertage) [BR-VOR-04]
reserviert_fuer_mich --> wartend : Mitglied gesperrt, Reservierung übersprungen [BR-VOR-06]
abgeholt --> [*]
wartend --> [*] : letztes Exemplar der Kategorie ausgemustert — Vormerkung bleibt bestehen [BR-VOR-09]
@enduml
----

Anmerkung zu BR-VOR-09:: Die Transition am unteren Rand ist bewusst kein Endzustand: die
Vormerkung bleibt in der Warteschlange, auch wenn aktuell kein Exemplar mehr existiert. Sie
verlässt die Warteschlange ausschließlich über `abgeholt` oder eine (in Release 1 nicht
vorgesehene) Stornierung.

== Validierungsregeln

[cols="1,2,3"]
|===
|Feld |Regel |BR-ID

|`Gegenstand.inventarnummer` |eindeutig, unveränderlich nach Anlage |BR-KAT-01
|`Gegenstand.kategorieId` |muss existierende Kategorie referenzieren, unveränderlich nach Anlage |BR-KAT-01
|`Gegenstand.wiederbeschaffungswertCent` |ganzzahlig, > 0 |BR-KAT-03
|`Kategorie.leihdauerTage` |ganzzahlig, > 0 |BR-KAT-02
|`Kategorie.wartungsintervall` |ganzzahlig, > 0 |BR-KAT-02
|Kaution (berechnet) |`round(wiederbeschaffungswertCent * 0.2 / 100) * 100`, kaufmännisch
gerundet *auf ganze Euro* (BR-KAT-04, `prd.adoc`), danach auf Intervall `[500, 10000]` Cent
begrenzt |BR-KAT-04
|`Ausleihe.mitgliedId` |Mitglied darf zum Zeitpunkt der Ausgabe max. 2 weitere aktive Ausleihen haben (insgesamt max. 3) |BR-AUS-02
|`Pruefprotokoll.kautionsabzugCent` |`0 <= Wert <= Ausleihe.kautionCent` |BR-KAU-02
|`Vormerkung (mitgliedId, kategorieId)` |Kombination höchstens einmal aktiv (`wartend` oder `reserviert_fuer_mich`) |BR-VOR-08
|`Reservierung.verfaelltAm` |`entstandenAm + 3 Kalendertage`, unabhängig von Öffnungstagen |BR-VOR-10
|`Einweisung (mitgliedId, kategorieId)` |höchstens ein nicht widerrufener Eintrag gleichzeitig gültig |BR-EIN-01
|===
