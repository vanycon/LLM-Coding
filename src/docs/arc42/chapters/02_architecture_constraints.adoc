== Randbedingungen

=== Organisatorische Randbedingungen (aus dem PRD, verbindlich)

[options="header",cols="1,3"]
|===
|Randbedingung |Quelle/Begründung

|Eine REST-API deckt alle Anwendungsfälle ab; zusätzlich eine CLI ausschließlich für den Wart;
keine Web-Oberfläche. |PRD, "Rahmenbedingungen": Ohne UI greifen Compiler und Testsuite als
Fehlerkorrektur voll, visuelle Konsistenz ließe sich nicht automatisch prüfen.
|Ein Prozess, lokal startbar, ohne externe Dienste. Kein Mailversand, keine
Zahlungsanbindung, keine Cloud. |PRD, "Rahmenbedingungen".
|Rollen werden über Header (REST) bzw. Flag (CLI) mitgegeben und *nicht kryptografisch
geprüft*. Echtes Login ist ausdrücklich nicht Teil des Systems. |PRD, "Rahmenbedingungen";
siehe Bedrohungsmodell <<section-concepts>>, T-004.
|Das aktuelle Datum wird über eine austauschbare Quelle gelesen. |PRD, "Rahmenbedingungen":
Fristen (Rückgabefrist, Reservierungsverfall, Sperre) müssen ohne Warten auf echte Zeit
testbar sein.
|Fachbegriffe im Code folgen dem Glossar des PRD (Ubiquitous Language). |PRD, "Sprache";
`AGENTS.md`, "Code Quality".
|Sprache, Framework und Persistenz sind frei wählbar. |PRD, "Rahmenbedingungen" — durch diese
Architektur konkretisiert auf Python, FastAPI, SQLite (siehe ADR-001, ADR-003, ADR-004 in
<<section-design-decisions>>).
|Verfügbarkeit ist kein Qualitätsziel. |PRD, "Qualitätsziele": zweimal wöchentlich geöffnet,
Ausfall dazwischen folgenlos.
|===

=== Technische Randbedingungen (durch diese Architektur festgelegt)

[options="header",cols="1,3"]
|===
|Randbedingung |Begründung

|Python 3.12+, ein einzelner Prozess (`uvicorn`-ASGI-Server). |ADR-001.
|Persistenz in einer einzigen SQLite-Datei, keine externe Datenbank. |ADR-004; passt zur
organisatorischen Randbedingung "ohne externe Dienste".
|Geldbeträge sind Ganzzahlen in Cent (keine Fließkommazahlen). |Vermeidet Rundungsfehler bei
der Kautionsberechnung (BR-KAT-04) — direkt aus Qualitätsziel "Korrektheit der Kaution"
abgeleitet.
|Die CLI enthält keine eigene Fachlogik; sie ist ein HTTP-Client der REST-API. |ADR-005;
verhindert zwei divergierende Implementierungen derselben Geschäftsregeln.
|===
