abgeschlossenen EPIC aktualisiert wird (`AGENTS.md`, Abschnitt "Implement Next": *"Verifiziere

`src/docs/arc42/chapters/08_concepts.adoc` (Abschnitt Test) dokumentierte Teststrategie an
konkreten Zahlen sichtbar und verknüpft jede Testdatei mit den Use-Case- und
Business-Rule-IDs, die sie abdeckt.

BR-KAT-05 und BR-KAT-06 sind absichtlich *nicht* in der EPIC-D-Testsuite abgedeckt — beide
Regeln lassen sich laut `katalog-pflegen.feature` erst durch eine laufende Ausleihe (UC-01)
bzw. eine abgeschlossene Prüfung (UC-04) beobachten und werden dort nachgezogen
(`src/leihgut/anwendungskern/katalog_service.py`, Docstring von `kategorie_aendern`).

BR-AUS-04 (Ausgabe-Ablehnung bei fehlender/widerrufener Einweisung) ist in EPIC-C nur zur
Hälfte abgedeckt: getestet ist, dass eine widerrufene Einweisung tatsächlich als ungültig gilt
(`Einweisung.ist_gueltig()`, `find_gueltige` liefert `None`). Die eigentliche Ausgabe-Ablehnung
entsteht erst mit dem Ausgabe-Anwendungsdienst in EPIC-A und wird dort Ende-zu-Ende getestet
(`einweisung-widerrufen.feature`, Szenario "Nach Widerruf wird die Ausgabe … abgelehnt").

== Offene Punkte

* Dieser Bericht wird von Hand aktualisiert. Eine automatisierte Einbindung von
  JUnit-/Coverage-XML in `generateSite` (z. B. über ein eigenes docToolchain-Template) ist
  noch nicht umgesetzt — bis dahin ist "aktuell" gleichbedeutend mit "nach dem letzten
  EPIC-Commit neu ausgeführt".
* CI (`.github/workflows/ci.yml`) führt `pytest -v` bereits bei jedem Push/PR aus, veröffentlicht
  aber noch keinen Coverage-Report als Artefakt.
