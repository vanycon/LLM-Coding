= ADR-003: Append-Only Audit Log

== Status

Accepted in the current implementation.

== Context

Audit history must not be changed through ordinary SQL UPDATE or DELETE operations. The domain has `AuditLogEintrag`, and SQLite triggers reject UPDATE and DELETE on the audit table. Evidence: `src/leihgut/domain/audit_log.py`, `src/leihgut/adapters/persistence/schema.sql`, and the audit triggers in `schema.sql`.

== Decision

Store audit entries in an append-only SQLite table and enforce immutability with database triggers. Expose audit statistics through the retention service and admin REST endpoint. Evidence: `src/leihgut/anwendungskern/audit_retention_service.py::get_audit_log_stats` and `src/leihgut/adapters/rest/app.py`.

== Consequences

Audit rows retain an immutable history and support statistics. Audit storage grows over time; retention policy logic exists, but its scheduling and operational procedure are not defined by the source. Audit coverage completeness for every state-changing use case is also unresolved.
