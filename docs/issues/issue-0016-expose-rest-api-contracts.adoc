== Description
Expose all release-1 use cases through the specified REST endpoints, DTOs, roles, statuses, stable errors, and atomic command behavior.

== Acceptance Criteria
[source,gherkin]
----
Given a REST request uses the documented endpoint and JSON contract
When the request is valid and authorized
Then the specified response body and success status are returned
Given a request is malformed, unauthorized, unknown, conflicting, or invalid
When it is processed
Then the common error shape and specified status are returned
Given a state-changing request fails
When the response is returned
Then no domain, audit, or deposit mutation remains
Given a caller submits a stale eligibility result to issue
When the issue request is processed
Then eligibility is re-evaluated in the issue transaction
----
